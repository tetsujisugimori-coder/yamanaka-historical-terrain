## D. B/C/Dと推定の管理

新規施設形状B=0、C=5。既存AとDは従来どおり。史料の文章や断面パラメータに根拠があっても、位置・全形・高さが未確定な施設全体をBへ昇格させない。`nishinomaru.json` の `evidenceParts`、`alternatives`、`articles` と安定IDを将来の記事・反証・改版の接続先にする。Blender extrasにはID、C、EPSG、原点、m単位、モデル版、UNKNOWNを保存する。

BlenderのsourceIdsは区域全体の参考文献集合で、各値がその施設の位置や寸法を証明するという意味ではない。施設部分ごとの支持範囲と不支持部分は `nishinomaru.json` の `evidenceParts` を正とする。例えば接続通路には隣接西櫓の記述を背景として関連付けるが、西ノ丸虎口位置の証拠とは明示的に区別する。

代替案は、(1) 図面の対応点と利用条件を確定して個別施設をB/Cに分割、(2) 1m現況面を優先した別のC平場案、(3) 第1期断面教材だけ継続。今回は立体区域を作れる一続きのC地表を選択。施設を重ね置きする方式は、Aが堀底を塞ぐため採用しない。歴史的原地表の排土・盛土量は算定していない。

## E. 実QGISによる地形・配置作業

QGIS 3.44.10のPyQGIS APIを実行し、第1期qgzを読込。EPSG:6676の1m DEMを施設範囲四隅でサンプリングし、最小・最大標高をGeoPackage属性へ保存。推定配置は `facility_envelopes`（重なり得る範囲であり実測施設ポリゴンではない）。独立した0.5m計算格子の推定GeoTIFFと、2断面・222標本のA現況1m / A Web三角形 / C比較を作成した。

`production/yamanaka-phase2a.qgz` は既存8レイヤーと新規2レイヤー。別フォルダへqgz・gis・phase2aを複製して実QGISで再読込し、相対参照と全レイヤーを確認。基準点0なので残差はUNKNOWNであり、0mと記入しない。ネイティブ終了コード0と内部完了票の両方を外部runnerが確認して初めてPASSを記録する。

## F. 実Blenderによる制作

Blender 4.5.9 LTSで第1期 `.blend` を実読込。原4メッシュを保持し、新規6メッシュを別コレクションへ生成。平場、堀底と畝、土塁の台形法面、通路、接続面は同じ地表式から作り、施設単位で別編集・差替え可能。元の現況三角形の対角線を継承し、110×105mの穴を復元側表示シェルにのみ設ける。

Blender X=東、Y=北、Z=標高。glTF X=東、Y=標高、Z=南、1unit=1m。標高原点は0m。標高誇張はWeb表示グループだけに適用。外周は実際のA GLB三角形面と1mm以内で一致し、C面の重複する境界頂点も一致することを別のNode計算で検査する。これは数値整合であり歴史的精度の証明ではない。

0.25m格子でC面369,600三角形と周辺シェル87,076三角形を出力。GLB約25MB、編集blend約42MB。35cmの丸い畝は簡略化され、約58度は切下げ関数のパラメータである。仮定平場の緩勾配・格子化・端部接続により全最終面が58度になるわけではない。精密CADや装飾建築物は今回不要と判断した。

## G. Web上の操作

「西ノ丸の復元候補」で区域全体を表示。施設はメッシュクリックまたはHTML一覧から選択。名称・役割・C・位置UNKNOWN・資料リンクを表示する。A現況/C復元の比較はカメラと注視点を保持。C全体と各5施設を個別に非表示にできる。非表示は面を除去するため空隙ができる旨をUIに明記。隠した施設をraycast対象からも除く。

曲輪/通路の低い観察視点、既存回転・パン・ズーム・キーボード回転・Resetを継承。連続自動アニメーションなし。WebGL不能・新GLB 404・描画接続喪失でも説明と出典は独立して読める。説明JSON自体の欠損は成功fallbackと報告しない。新しい読込後に取消済みの古い失敗が到着しても現在の表示を破壊しない。

GitHub Pagesのリポジトリサブパスに対応する既存BASE_URLを維持。本変更を公開デプロイしていない。レビュー用はローカル `npm run dev`、PRの画像と編集ファイル。従来の公開URLが本期モデルを配信済みとは主張しない。

初回の失敗を保存する。QGIS生成は原点3成分を2変数へ展開したコードエラー、後続Blenderはその出力欠損で停止（両方終了1）。修正後は原点の水平2成分を明示して成功。QGIS再読込試験は期待11レイヤーと誤記し、実際は原8+追加2=10。原qgzから期待数を導出するよう修正。旧QGIS内部nativeクラッシュとは別の原因である。

最初のメッシュ選択試験は、モバイルで操作パネルへスクロール後に画面外座標をクリックするテスト不備。画面内へ対象を戻し座標を再計測するよう修正した。負対照が検出できなかった初回結果も残し、読込順序は待ち時間から明示的な解放ゲートへ変更した。これらを製品の旧版FAILとして誤報しない。追加途中のChromium 375/reduceで新GLB requestfailedと25秒timeoutが1件発生。制作物再出力・開発サーバー更新が並行していたが、厳密な因果は未確定でUNKNOWN。最終版は成果物を固定した静的ビルドで検査し、元失敗は保持する。既知の第1期QGIS内部クラッシュの厳密原因とブラウザ読込timeoutの根本原因も引き続きUNKNOWN。再実行成功で解明済みにはしない。
